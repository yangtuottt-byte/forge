## 一、学到的核心概念(用自己的话)

### 1. 可观测性三支柱 ⭐
| 支柱 | 回答什么 | 实现 |
|------|---------|------|
| Logging | 发生了什么? | JSON 结构化日志 |
| Metrics | 系统状态如何? | QPS/延迟(未做) |
| Tracing | 请求怎么流转? | 链路 ID(未做) |

**结构化日志**:JSON 格式,每条带 timestamp/level/service/message,便于日志系统检索。

### 2. 限流 ⭐
- **滑动窗口**:记录每个客户端的请求时间戳,只算窗口内的请求
- 超出返回 429(Too Many Requests)
- 防滥用(恶意请求)、防过载(系统扛不住)

### 3. Docker Compose 多服务 ⭐
- 一键起全套:API + Worker + PG + Redis
- `depends_on` 管依赖顺序,`environment` 传配置
- **容器间通信**:服务名(DB_HOST=pg)不是 localhost

### 4. Dockerfile ⭐
- 基础镜像 + 装依赖 + 复制代码 + 启动命令
- 先装依赖(利用缓存:代码改了依赖不用重装)

### 5. ADR(架构决策记录)⭐
- 记录"为什么选 A 不选 B"
- 后人理解决策,不重复踩坑
- 格式:背景/决策/理由/影响/替代方案

## 三、踩坑记录(自己写代码时遇到的)

1. **中间件签名错误**:`__init__` 没接收 `app` 参数 → "multiple values for max_requests"。**修复:加 `app` 参数**。
2. **中间件类型错误**:Starlette 风格(`__call__(request, call_next)`)→ FastAPI 期望纯 ASGI(`__call__(scope, receive, send)`)。**修复:改纯 ASGI**。
3. **compose key 拼错**:`environments`(复数)→ 应该是 `environment`(单数)。**修复:改单数**。
4. **compose condition 拼错**:`ondition`(少 c)→ `condition`。**修复:补 c**。
5. **容器名通信**:容器间用服务名(DB_HOST=pg)不是 localhost。
