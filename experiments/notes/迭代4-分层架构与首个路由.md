## 一、学到的核心概念(用自己的话)

### 1. 分层架构(本迭代灵魂)
请求的理想分流:
```
浏览器 GET /api/v1/health
   ↓
① API 层(路由):接收请求、调 service、返回响应 —— 不写业务逻辑
   ↓
② Service 层(业务逻辑):编排、决策 —— 不碰 SQL、不碰 HTTP
   ↓
③ Repository 层(数据访问):唯一碰数据库的地方
   ↓
④ Model 层(ORM):User ↔ users 表
```
**价值**:每层可单独测试、各司其职。路由层不写 SQL,改表结构不动路由;改 API 不动数据库。

### 2. FastAPI 生命周期(lifespan)
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    ...  # yield 之前=启动:初始化、预热
    yield
    ...  # yield 之后=关闭:还池、释放
```
类似 Flask 的 `before_first_request`/`after_app_context`,但明确了**应用整个生命周期**。

### 3. 路由挂载
- `APIRouter()` 建子路由;`include_router(router, prefix=...)` 挂到 app
- **api_router 汇总点**:新增的路由只需加进 `router.py`,main.py 不动 —— 扩展点设计

### 4. response_model 与 pydantic schema
- `response_model=HealthResponse`:FastAPI 按 schema 校验+序列化输出
- schema 即文档:Swagger 页与 openapi.json 自动生成(**Flask 无此能力**)
- Swagger UI:`/docs` —— **FastAPI 杀手锏**,写接口约等于写文档

### 5. ASGITransport 测试
httpx 的 ASGI 直连 app,**不发真实 HTTP、不开端口**,测试速度且环境干净。

### 6. ⭐ 事件循环复用坑(测试基础设施)
pytest 每个 async 测试在**独立事件循环**跑,但 async engine 连接池里的连接**"记住"它被使用时的 loop**。不清池 → 下一个测试拿到旧 loop 的连接 → `Event loop is closed` / 连接失效。
**解法**:`tests/conftest.py` + autouse fixture,测试前 `engine.dispose()` 清空连接池。
⭐ **教训**:debug 这件事时,看完整 traceback——抓到 `Event loop is closed` 才明白是 loop 隔离,不是代码错。

## 二、关键代码模式

| 模式 | 代码 | 用在哪 |
|------|------|--------|
| 应用工厂 | `app = FastAPI(title, version, lifespan=lifespan)` | main.py |

| 夹具分离 | `tests/conftest.py` 共享 fixture | tests/conftest.py |

## 三、踩坑记录(自己写代码时遇到的)

1. **`main.py` 保存了空文件**:文件存在但 0 字节,`Attribute "app" not found`——以为"写完"了,实际编辑器里的内容没落盘。(前面迭代已有"改完忘保存"事故,这是第二次——**养成习惯:文件写完先 `cat` 自己检查一遍**。)
2. **async engine 的事件循环复用**:全量跑测试时,`test_db` 通过,`test_health` 返回 `{"status": "degraded", "db": False}`(没报错!静默降级!)——`check_database` try/except 通吃一切错误,把 loop 问题伪装成"数据库不可用"。**教训:捕获 Exception 要谨慎,测试要能区分"真错误"和"环境问题"** → 用 conftest.py + dispose 在测试层解决。
3. **`make` 在 backend/ 目录跑报 No rule**:Makefile 在仓库根目录 —— 文档第一行:从根目录跑 make,从 backend 跑 pytest/ruff 直接一点。
4. **`pgrep -f uvicorn` 匹配到自己**:`pgrep -f` 匹配整个命令行,包含自己的 shell 命令 → 假进程。看真实状态用 `ss -tlnp`(端口)。
5. **格式修复对象**:`make format` 第一季度 autorepair 的坑都是 W293 尾随空格(编辑器行为),下一迭代注意"写完一个文件先 make format"。
6. **测试基础设施的优先级**:conftest.py 坏了全测试挂,它应先保证"绿";功能测试后面再补——这些在"测试决定论"中都讲明白了。

## 四、面试可能问

| 问题 | 答案要点 |
|------|---------|
| 分层架构中每层职责? | Route 收发;Service 业务逻辑;Repository 数据访问;Model 表映射——各司其职、可单测 |
| 为什么路由层薄? | 路由只做协议转换(入/出),不含逻辑——逻辑放 Service,可复用、易测 |
| FastAPI lifespan 是什么? | 应用生命周期钩子:启动(yield前)初始化、关闭(yield后)释放——类比 Flask 中间件但更明确 |
| include_router 有什么用? | 路由挂载:子 router 挂到 app 上,支持 prefix;新增路由只动 router.py,main.py 不变(扩展点) |
| Swagger 文档为什么不用写? | FastAPI 从代码(路由+schema)自动生成 OpenAPI,/docs 渲染——Flask 要单独装扩展+手写或手维护 |
| 什么是 ASGITransport? | httpx 的传输层:直接调 app,不发网络请求。非法测试异步 app 的标配 |
| pytest 怎么测 async 应用? | asyncio_mode=auto 让 async def 直接跑;用 ASGITransport + AssertClient。**连接池与事件循环撞车**要用 conftest 夹具处理 |
| 事件循环复用坑的表现? | 测试独过时过、全量跑挂;报错 Event loop is closed / 连接失效;解法是每个测试后 dispose pool |
| 捕获 Exception 会掩盖什么? | 真实部署中,`except Exception: return False` 会把配置错误/权限错误/依赖故障全吞掉——要么细化 except,要么记日志,测试要能发现 |
| 什么场景用 conftest.py? | 放多个测试文件共用的 fixture/钩子(API client、DB session 等)——测试基础设施层 |
| /docs 接口文档从哪来? | 由 FastAPI 自动生成 OpenAPI spec(代码+schema),Swagger UI 渲染 /docs |
| 仓库根目录运行 vs backend目录? | Makefile 在根目录,pytest/ruff 配置在 backend——**环境切换点**:根目录 make 是默认约定 |

**结论**:

3. ✅ **FastAPI 全自动文档**:写 `response_model`,Swagger/openapi 自动生成——这就是项目选择 FastAPI 的理由

**观察**:
- `include_router` 会递归挂载,第二个路由文件只需注册到 router.py —— 扩展性在结构里成立,不靠"以后改 main.py"糊出来
