## 一、学到的核心概念(用自己的话)

### 1. Celery = 分布式任务队列 ⭐
- 三组件:Broker(Redis 排队)/ Worker(执行)/ Backend(存结果)
- 流程:API 丢任务到 Redis → 立即返回任务ID → Worker 消费执行
- **为什么异步**:Agent 任务慢(LLM 几分钟),同步会阻塞 API

### 2. 任务状态持久化 ⭐
- agent_tasks 表:status/progress/result/created_at
- 状态机:pending → running → done/failed
- **为什么持久化**:前端查询、崩溃恢复、审计

### 3. WebSocket 实时进度 + Redis pub/sub ⭐
- **关键问题**:Worker 和 API 不同进程,跨进程通信用 Redis pub/sub
- Worker publish 进度 → Redis → API 订阅 → 转发 WebSocket
- 对比轮询:WebSocket 实时推送,不浪费

### 4. 分布式锁 / 幂等 / 重试 / 死信 ⭐
| 防护 | 作用 | 实现 |
|------|------|------|
| 分布式锁 | 防重复执行 | SET NX EX + finally 释放 |
| 幂等 | 同一任务不重跑 | status == "done" 跳过 |
| 重试 | 失败自动重试 | Celery autoretry(max_retries=3) |
| 死信 | 重试耗尽人工处理 | status=failed |

### 5. LLM 测试的不确定性
- LLM 测试偶发失败(模型有时直接回答不调工具)
- **教训**:LLM 测试要宽松断言,或单独跑验证

## 三、踩坑记录(自己写代码时遇到的)

1. **PG 容器频繁挂掉**:docker compose ps 空表,ConnectionRefused。**教训:长时间不操作容器被回收,定期检查**。
2. **LLM 测试限流**:星火 API 免费版限流,LLM 测试频繁触发。**修复:conftest hook 限流感知(skip 不 fail)**。
3. **LLM 测试偶发失败**:test_agent_loop_calculator 全量跑失败,单独跑通过。**教训:LLM 不确定性,测试要宽松**。
4. **Celery 任务同步 vs 异步**:Celery 任务是同步的,Orchestrator.run 异步,用 asyncio.run 包裹。
5. **WebSocket 跨进程**:Worker 推送进度不能直接访问 API 连接池,用 Redis pub/sub 桥接。

## 四、面试可能问

| 问题 | 答案要点 |
|------|---------|
| Celery 是什么? | 分布式任务队列,Broker/Worker/Backend 三组件 |
| 为什么 Agent 任务要异步? | Agent 任务慢(LLM 几分钟),同步阻塞 API |
| 任务状态为什么持久化? | 前端查询、崩溃恢复、审计 |
| Worker 和 API 不同进程怎么通信? | Redis pub/sub |
| WebSocket vs 轮询? | WebSocket 实时推送,轮询浪费 |
| 分布式锁怎么防重复执行? | SET NX EX + finally 释放 |
| 幂等怎么实现? | task_id + 状态检查,已 done 不重跑 |
| 重试怎么实现? | Celery autoretry + retry_backoff |
| 死信队列是什么? | 重试耗尽的任务,人工处理 |
| finally 释放锁的意义? | 保证不死锁(异常也要释放) |
